# 微光球场 · ORBIT

一个使用 Flask、原生 JavaScript ES Modules、Canvas 2D 和 SQLite 的吞噬小游戏，支持单机与局域网真人 + 人机联机。无图片素材、无前端打包步骤、无 npm 运行时依赖。

## v0.10.0：同步优化、2v2 团队与手机摇杆

- **减少联机流量**：食物首次全量下发，随后发送带版本号的增量；慢连接直接从上次实际发送的基线合并到最新状态，换位、重连或基线失效时可全量恢复。世界事件按连接游标发送，球体只同步公开字段；全量食物编码在同一帧内复用。30Hz 权威模拟稳定提供 20Hz 最新状态广播，卡顿后不补发过期快照。
- **画面更稳定**：对手位置按服务器时间在快照之间插值，缓冲随抖动在 50～130ms 间调整，快照暂缺时最多外推 100ms；自己的绘制位置保留最多 120ms 外推。质量、吞噬、生命和胜负始终由服务器计算。技能按下立即发送，普通移动保持约 30Hz。状态条增加实际接收的 JSON 下行 KB/s，悬停查看抖动和插值缓冲。
- **房主设置规则**：可选生存乱斗或 **2v2 团队**，时长 **3 / 5 / 8 分钟**；仅房主能在准备室调整。改规则后全员重新准备，团队成员变化也会取消准备，正在重连的成员恢复后才能开局。空位自动补人机至 4 人。
- **团队玩法**：按席位交替加入薄荷队与星云队，每队 2 人；队友不能互吃，可吐孢子喂队友，人机也遵循同队规则。顶部显示团队命数、击败和质量，球体与标签标记队友。时间到按 **团队总命数 → 总击败 → 总质量** 排名，可并列；只剩一队提前获胜。个人出局后观战，仍可随队友获胜。
- **手机操作**：触屏或窄屏显示左侧摇杆，支持死区、拖动强度与对角限速，松手、取消或失焦即停止；右侧技能可同时操作，小地图上移避让。鼠标左右键和 Q/E 操作继续保留。
- **边界修正**：恢复凭证失效后返回加入页，停止无效重试；结算后排行明确显示“本局已结算”，不会因停止推送世界而误报高延迟。服务端同步取消旧冲刺指令，手工发送 Shift 冲刺也不会生效。碰撞网格减少重复查询范围与无用重建，增重后及时补入新覆盖网格。

设计参考与独立实现范围：

- [agar.io-clone](https://github.com/owenashurst/agar.io-clone)：参考浏览器吞噬游戏的服务端更新与移动端操作思路。
- [MultiOgarII](https://github.com/m-byte918/MultiOgarII)：参考独立游戏模式、团队归属与同队吞噬限制的组织方式；本项目采用自己的三命生存、时间限制与团队结算规则。

以上均为本项目内独立编写的 Python / JavaScript 实现，没有复制第三方源码，也没有引入 Node.js 或 C++ 游戏服务端。房间规则独立放在 `server/game/rules.py`，传输增量放在 `server/replication.py`，方便继续扩展模式与同步协议。

本机固定场景实测（4 名人机、初始 32 分身、560 食物、种子 42、300 tick / 10 秒模拟时间，统计一个客户端取走的 JSON 消息）：

| 指标 | v0.9.3（`0af35ac`） | v0.10.0 |
| --- | ---: | ---: |
| 平均模拟 tick | 3.631 ms | 2.722 ms |
| P95 模拟 tick | 5.142 ms | 3.984 ms |
| 持续下行 | 526.25 KB/s | 217.58 KB/s |
| 10 秒状态消息 | 150 | 200 |

该场景持续下行减少 **58.7%**；旧版广播计时余量丢失，实际约 15Hz，新版修正为 20Hz。消息体积不含 WebSocket/TCP 帧开销，tick 时间不含网络发送与客户端绘制；结果随设备和局面变化，不代表公网延迟或所有场景的性能。复测命令见文末。

## v0.9.3：联机人机补位

- **真人不足自动补位**：联机房间支持 1～4 位真人，真人全部准备后即可开始；服务器会把空位补成最多 3 名人机，凑足 4 名参赛者。单人创建房间也能直接开始，不再必须等待朋友。
- **人机使用权威规则**：人机在服务器端追食物、躲避更大的球、追击可吞噬目标，并参与食物、孢子、刺球、吞噬、生命、复活和排行榜。客户端不能伪造或操控人机输入。
- **联机纪录只统计真人**：结算保存最高分时只取真人成绩，人机成长不会覆盖玩家的本机最高分。

## v0.9.2：分身管理、断线恢复与空间分区

- **分身管理更清楚**：HUD 显示当前分身数、总质量、最大分身质量和最小分身质量；当前最大分身在画布上有额外高亮，8 个分身时也能快速识别主分身。分身上限继续保持 8 个。
- **断线可恢复**：普通网络断开后，服务器保留玩家、房间和对局实体 **10 秒**。客户端自动退避重连，恢复时沿用原玩家 ID、昵称、房间、排行榜身份和服务端分身；恢复期间房间成员会显示“重连中”。主动退出仍立即离开房间，超过 10 秒未恢复才按离线处理。
- **空间分区碰撞**：单机和联机都使用均匀空间网格筛选附近食物、孢子、刺球和球体吞噬候选，再用原有精确距离与质量规则确认碰撞。大球成长后查询半径会自动扩大，不会漏掉边缘接触的食物。

## v0.9.1：鼠标技能与八分身

- **鼠标技能**：鼠标左键吐孢子，鼠标右键分身；键盘 `E` / `Q` 和移动端技能按钮继续可用。右键已禁用浏览器菜单，技能仍通过统一输入协议进入单机与联机规则。
- **八分身**：单机和联机的分身上限从 4 个提高到 **8 个**，服务端权威快照同步显示新的上限。

## v0.9.0：吐孢子与扎刺玩法

- **吐孢子**：按 `E` 或点击技能按钮，从质量至少 48 m 的最大分身中吐出一个 8 m 孢子，冷却 0.45 秒。孢子沿移动方向飞出，任何玩家或 AI 都可以吃掉它；吐出质量不直接增加分数。
- **扎刺**：地图固定生成绿色刺球，达到 72 m 的球撞上刺球后会被弹开、损失 8% 总质量并按当前方向分裂；分身上限已满时仍会损失质量并弹开。刺球有短暂触发保护，避免连续触发。
- **移除 Shift 冲刺**：Shift 不再触发加速，也不再显示冲刺按钮或提示。原有分裂、合体、生存模式、联机和排行榜继续可用。
- **联机同步**：孢子、刺球、分身、吐出/吃掉/扎刺事件由 Python 权威服务器计算，客户端只发送移动目标和 `split` / `spore` 输入并绘制权威快照。

## v0.8.1：联机延迟、房间和排行优化

- **输入更及时**：客户端每秒发送 30 次输入，服务器保持 30Hz 权威模拟并以 20Hz 广播状态；客户端根据服务器速度做最多 120ms 的视觉外推，降低快照间隔造成的停顿。体重、吞噬、生命和分数仍只由服务器决定。
- **连接状态可见**：联机状态条显示 RTT 和“连接良好 / 连接一般 / 延迟较高”，准备室和对局中都能及时发现 Wi-Fi 波动。排行面板显示最近一次权威快照的同步年龄。
- **准备室更清楚**：显示 `已准备人数 / 房间人数`，未满足条件时告诉你还差几人；房间号输入自动过滤非数字字符，减少手机输入错误。
- **排行更易读**：排行行显示名次变化（↑ / ↓），玩家仍保留自己的完整名次；排行继续按生存规则的命数、击败数、总质量排序。


## 联机玩法（当前版本）

- 开始页的“对局模式”选择 **联机 · 真人 + 人机**。填写昵称，选择玩法与时长后创建房间，再分享邀请链接或 **6 位数字房间号**；朋友填写不同昵称加入。真人可以 1～4 人，**包括房主在内的所有真人准备**后，房主点击“开始对局”；不足 4 人的空位由服务器自动补人机，对局进行中不接受加入。
- 每人 **3 条命、36 m** 开局。被吃掉最后一个分身才扣 1 命，有命立即以 36 m 复活，保护 3 秒；吃掉别人最后一个分身加 1 命。吞噬者正常增重，只重置被吃者，其他人体重保持当时数值。分裂、10 秒后合体、吐孢子、扎刺、富集区、音乐和轻音效继续可用。
- 时长由房主选择 **3 / 5 / 8 分钟**，默认 5 分钟，所有人使用同一个服务器时钟。生存乱斗按 **剩余命数 → 击败人数 → 当前总质量** 排名，最后一位幸存者提前获胜；2v2 按队伍合计统计，最后一个队伍提前获胜，队友不可互吃且可用孢子相互喂养。相同成绩并列。出局后进入观战，由服务器统一结算；结束后房主点击“返回准备室”，所有人重新准备即可再来一局。
- **联机不能暂停**。切走页面、失去焦点或按空格，只停止自己的操作，对局继续；返回页面或点击画布恢复控制。主动退出、刷新或关页会离开房间；普通网络断开保留 10 秒恢复窗口，超过窗口才按离线出局。准备室房主离开时自动移交房主。
- 移动、食物、吞噬、技能、生命、复活、排名和时限均由 **Python 权威服务器**计算。客户端只发送输入、接收快照并平滑绘制位置，不能提交体重、命数或联机分数。服务器每秒模拟 30 次、广播状态 20 次，客户端普通输入约 30Hz，技能可立即发送；对手绘制使用自适应插值与有上限的外推，权威规则仍在服务器。
- 联机最高分在对局结束时由服务器写入现有 SQLite；全员中途退出也保留已计算的分数。写库短暂失败会重试，保存完成后通知在线浏览器更新记录。单机经典、单机生存和原有数据库继续保留。

### 和朋友联机启动

先按下方“启动”安装依赖；从旧版升级也需要再运行一次：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Windows 双击 **start-lan.bat**，保持启动窗口打开。它监听 `0.0.0.0:5000`，窗口会打印本机局域网网址。本机可以访问 `http://127.0.0.1:5000/`，朋友需要在 **同一 Wi-Fi / 局域网**打开窗口打印的网址，例如 `http://192.168.1.23:5000/`；具体 IP 以自己的电脑为准。

房主创建房间后复制邀请链接。即使房主通过 localhost 打开页面，链接也会优先采用本机局域网地址；局域网 HTTP 无剪贴板权限时，可选中显示的链接手动复制。房间号只在当前服务器中有效，朋友必须访问房主电脑的同一个服务。换 Wi-Fi 后应重新查看局域网地址。

macOS / Linux，或需要手动启动时：

```bash
# macOS / Linux
HOST=0.0.0.0 .venv/bin/python app.py
```

```powershell
# Windows PowerShell
$env:HOST = "0.0.0.0"
.\.venv\Scripts\python.exe app.py
```

若 5000 端口已被旧服务占用，先在旧启动窗口按 Ctrl+C，再启动新服务。朋友打不开时，检查两台设备是否在同一网络、Windows 防火墙是否允许该 Python 的专用网络连接，以及 Wi-Fi 是否开启了访客隔离。浏览器刷新旧版本可用 **Ctrl+F5**。

房间保存在单进程内存中，重启服务会清空房间，最高分仍保留。断线恢复只在同一服务进程的 10 秒窗口内有效；公网部署、账号和多进程共享房间仍需后续扩展。请通过 `app.py` / 启动脚本运行，以启用本项目的 WebSocket 请求处理器。

## v0.7：5 分钟生存模式

- 在开始页或结算页的“对局模式”中选择 **生存 · 5 分钟**，再点击开始；经典模式继续可选，浏览器记住模式选择。一局进行中不能切换规则，暂停继续和重新开始不会意外切换。
- 你与 13 位 AI 均以 **3 条命、36 m** 开局，名单固定。被吃扣 1 命，仍有命则立即以单球 **36 m** 在远离其他球的位置复活，带 **3 秒保护**。命数归零后出局；玩家归零立即结算。吃掉一个人加 1 命，命数不设上限。
- **吞噬照常增重**；复活只重置被吃者的体重、位置和技能，不重置任何其他参赛者。累计分数、阶段、食物与对局时钟保留。保护期间不能吃人也不能被吃，玩家和 AI 遵守相同规则。
- **按人计算死亡**：只丢一个分身不扣命；最后一个分身被吃才扣 1 命，由吃掉最后分身的人获得 1 命。吃普通分身仍增加质量和分数，不重复发命。同一帧处理完吞噬后才生成复活球，避免瞬间连续扣命。
- 对局最多 **5 分钟游戏时间**，暂停、切走页面和失去焦点会冻结倒计时。时间到按 **剩余命数 → 击败人数 → 当前总质量** 排名，三项相同则并列；最后一名幸存者提前获胜。生命条显示命数、倒计时、击败数和存活人数，普通/专注/手机布局都可见。排行按生存规则排序，球下方同时显示命数。
- 生存模式关闭经典模式的 AI 补位及难度替换，避免给出局者重新发命或改变其他人体重；AI 仍正常觅食、追逐、避让、分裂与合体。最高分继续共用原有 SQLite 记录，无需迁移数据库。

## v0.6：标签避让、技能就绪提示与富集区换位预告

- **标签避让**：质量标签统一在屏幕坐标中排布，优先保留玩家分身，再显示危险 AI，避开球体、其他标签、排行榜、技能面板和小地图。移开较远的标签以细线指向对应球体；极拥挤时隐藏放不下的低优先级 AI 标签。镜头拉远后，距离玩家较远的 AI 只显示质量，附近 AI 仍保留危险/可吞噬说明。
- **技能就绪提示**：分裂、吐孢子从不可用变为可用时，按钮边框轻亮 **0.9 秒**，包括冷却结束、质量达到条件或分身名额重新空出。开局已有的技能不会闪亮，保持就绪不会重复提示；暂停冻结提示和动画，重开清除旧提示。不增加声音或操作步骤。
- **富集区换位预告**：最后 **5 秒**，左上角倒计时的文字和边框变为金色，小地图当前区域的金圈加亮；换位后，新区域在小地图高亮 **3 秒**并渐隐。暂停冻结高亮时长，重开清除。尊重系统的“减少动态效果”设置，以静态边框代替技能动画，并关闭地图高亮的扩散动作。

## v0.5：轻音效、质量显示、实时排行与食物富集区

- **轻音效**：吃食物、吞噬对手、分裂、合体、吐孢子、扎刺和失去分身各有简短的合成音。右上角喇叭按钮独立控制音效，选择保存在浏览器；关闭音乐或把音乐音量调到 0，音效仍可使用。音效保持轻音量，连续吃食物至少间隔 140 毫秒，同一帧优先提示吞噬与技能，不密集叠音。开始/继续游戏后才解锁声音，暂停、结束和关闭音效会停止旧声音。
- **质量显示**：玩家和 AI 球下方显示各自当前质量，单位 `m` 代表游戏内质量；分身分别显示自身质量。专注模式顶栏和技能面板显示球群总质量，能直接看到吐孢子、扎刺和损失分身的影响。累计得分与当前质量分开计算。
- **实时排行**：画布右上角显示本局总质量前五名，每秒最多更新 10 次。同一控制者的所有存活分身合并排名，玩家行高亮；即使不在前五，也显示自己的名次、参赛控制者数与总质量。按精确质量排序，显示数值四舍五入；同质量按控制者 ID 稳定排序。手机默认收起，点击“本局排行”可展开或收起，键盘聚焦标题后按空格也可操作。
- **食物富集区**：地图上始终有两处金色虚线圆圈 A/B，小地图同步标记，左上角显示换位倒计时。每 **45 秒游戏时间**换位，暂停时冻结，重开重置。新食物有 **36% 概率**生成在富集区；换位时迁移旧区域食物，并补足约 36% 的存量食物在新区域，避免多次换位后密度下降。食物上限仍为 **560**，单点质量仍为 1，AI 和玩家遵守相同的觅食规则。富集区只改变分布，不额外刷分。

## v0.4：轻柔背景音乐

- **循环配乐**：用 Web Audio 合成 76 BPM 的原创八小节旋律，搭配柔和和弦、低音与短回声；不需要额外下载音频文件。
- **开始后播放**：首页保持安静，默认在点击“开始游戏”后以 30% 音量播放，以满足浏览器的声音播放限制。
- **随时调节**：右上角音符按钮开关音乐，旁边滑块调节音量；选择保存在当前浏览器，刷新和重开后仍保留。音量为 0 时停止播放，把音量调高即可恢复。
- **跟随游戏状态**：暂停、切走页面、窗口失去焦点、游戏结束时淡出并停止安排新音符；继续时恢复，重新开局从第一小节重新播放。浏览器暂时阻止音频时，继续游戏或操作音乐控件可再次尝试；不支持音频的浏览器仍能正常运行游戏。

## v0.3：分裂与合体

- **分身规则**：朝当前操作方向将合格分身一分为二，单球质量至少为 **72**，最多同时存在 **8 个分身**。每次优先分裂最大的球，每个原有球最多分裂一次；按键间隔为 0.75 秒，长按不会自动连发。没有方向且完全静止时不会触发，也可点击左下角分身按钮。
- **弹射与操控**：新分身短距离弹出，每个分身有独立质量、半径、速度和吞噬判定。鼠标/触屏控制共同目标位置；WASD/方向键控制共同移动方向。镜头跟随按质量加权的球群中心，并随分散范围自动拉远，小地图显示每个分身。
- **自动合体**：新分身和其母球重新等待 **10 秒**；两球冷却均结束后会自动靠拢，接触后合体，无需再按键。冷却前分身互相避让；圆环和 HUD 显示等待进度。球群分散较远时，靠拢需要额外时间。
- **质量与分数**：分裂、合体都不损失总质量，也不改变累计分数。吞噬按单个分身计算，不能用球群总质量吃掉大球；同属一个玩家或 AI 的分身不能互相吞噬或刷分。
- **保留生存机会**：一个分身被吃后继续操控剩余分身，全部被吃才结束。失去分身会损失它的质量，但累计分数、阶段和已达到的难度保持不变。
- **与新玩法兼容**：吐孢子和扎刺都按单个分身质量处理；暂停冻结弹射、分裂、吐孢子冷却和合体等待，重开会清空分身与技能状态。
- **追猎者 AI**：前两名追猎者在分裂后仍足够吃掉目标、且附近没有强敌时，可向目标分裂追击。每名最多两个分身，技能冷却 14 秒，也遵循合体和同属关系规则。AI 数量配额按控制者计算，不会因分身而减少其他对手的补充。

## v0.2 升级

- **动态难度**：难度随阶段和生存时间逐步提高；新 AI 体型参考本局最大质量。场上分为觅食者、游猎者、追猎者三类，保留小球、中等对手和强敌。每 8 秒最多替换一个视野外的落后 AI，优先补充追猎者；现有 AI 不会突然变大。
- **公平出生**：新 AI 的整个球体和 100 像素缓冲区必须位于视野外，并远离玩家与其他 AI。找不到安全位置时延后刷新。
- **阶段目标**：依次达到 300、800、1500、3000、5000、8000 分，再按约 1.5 倍继续递增。进度条显示当前阶段的区间进度，达标时弹出提示；一次跨过多个阶段只提示最后达到的阶段。
- **专注模式**：默认开局收起标题和侧栏，扩大画布，同时保留得分、最高分、时间、难度、阶段和技能 HUD。按 `F` 或点击工具栏按钮切换；手动选择会被记住，选择普通视图后重开不会强制进入专注模式。

从旧版升级请更新源码、安装最新 requirements 并重启 Flask 进程，再刷新页面。数据库结构未变，`instance/game.sqlite3` 中的历史最高分会保留。

## 启动

需要 **Python 3.9 或更高版本**，以及支持 ES Modules、Canvas、WebSocket 的现代浏览器。运行游戏不需要 Node.js。

在项目目录打开终端，运行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

浏览器打开 **http://127.0.0.1:5000**。不需要激活虚拟环境，也不需要手动建库。按 `Ctrl+C` 停止服务器。不要直接双击 `index.html`，页面和 API 必须通过 Flask 提供。

Windows 完成首次安装后，也可双击项目目录的 `start.bat` 启动。游戏期间保持启动窗口打开；关闭窗口或停止 Python 后，浏览器会显示 `ERR_CONNECTION_REFUSED`（拒绝连接），此时重新运行 `start.bat` 再刷新页面即可。

macOS / Linux：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py
```

端口被占用时，在 PowerShell 设置 `$env:PORT = "5001"` 后再启动，并访问相应端口。`app.py` 是本地开发入口；公开部署时应另行配置生产 WSGI 服务。

## 怎么玩

- 点击“开始游戏”，小球会朝鼠标方向移动；鼠标越靠近球心，速度越慢。也支持方向键、WASD、触屏拖动及左侧虚拟摇杆，右侧技能可同时操作。
- 吃食物增加质量和分数；面积随质量增长，速度随质量增加而降低。
- 质量至少为对方的 **1.28 倍**，且对方球心进入 `大球半径 - 小球半径 × 0.35` 的范围时，才会吞噬。
- 吃掉 AI 分身获得它当前质量四舍五入后的分数；全部玩家分身被更大的 AI 吞噬才会结束。开局前 3 秒，所有玩家分身和 AI 之间都不会发生吞噬。
- `Space` / `Esc` 暂停或继续，`R` 重开。切走页面、窗口失去焦点时自动暂停。
- 鼠标右键或 `Q` 分身，10 秒后自动靠拢合体；鼠标左键或 `E` 吐孢子，撞上绿色刺球会扎刺分裂；`F` 切换专注模式。暂停会冻结技能与合体计时；重开会重置本局技能、阶段和难度。
- 右上角可以切换深色与浅色模式；主题会保存在浏览器中。
- 右上角音符按钮控制背景音乐，旁边滑块调音量；音乐随暂停和结束停止，重开保留开关与音量选择。
- 右上角喇叭按钮独立控制轻音效；滑块只调背景音乐音量。到金色 A/B 圈里可更密集地找到食物，换位倒计时位于画布左上角。
- 球下方的 `m` 是自身质量；技能面板和专注顶栏显示总质量。右上角本局排行按玩家或 AI 的总质量统计，点击标题可收起。
- 单机最高分每 5 秒、暂停、重开、游戏结束时自动保存。接口暂时不可用时，分数暂存在浏览器里并自动重试；正常保存后以 SQLite 数据库为准。联机最高分由服务器在结算时保存。

## 分数 API 与数据库

`GET /api/high-score`：

```json
{"high_score": 120, "updated_at": "2026-10-24T08:00:00.000Z"}
```

`POST /api/scores`，请求头 `Content-Type: application/json`：

```json
{"score": 180}
```

返回最新的 `high_score`、`updated_at` 和本次是否刷新记录的 `is_new_record`。非法分数返回 400，非 JSON 请求返回 415。分数必须为 0～1000000000 的整数。初始记录为 0，更新时间为空。

SQLite 的 `records` 表保存一个最高分，使用 SQL 条件更新，较低分不会覆盖较高分。本版没有账号，**同一个 Flask 实例共用一份最高分**。数据库保存在 `instance/game.sqlite3`，停止应用后可复制此文件备份。

## 修改玩法与继续扩展

优先修改 `static/js/config.js`：`food.count` 是食物数量，`bots.count` 是 AI 控制者数量，`player.baseSpeed` 是基础速度，`rules.eatMassRatio` 是吞噬质量比例。`split` 控制分身上限、分裂最低质量、技能冷却、合体等待、弹射速度和 AI 分裂限制；`spore` 控制孢子质量、最低质量、冷却、飞行速度和寿命；`spikes` 控制刺球数量、半径、扎刺损耗与保护时间；`milestones` 定义前几级阶段目标；`difficulty` 控制刷新间隔、出生缓冲区和 AI 规模上限；`hotspots` 控制富集区数量、半径、换位间隔和食物比例；`survival` 控制时限、初始命数及复活保护时长；`effects` 控制音效音量、最大声部数和触发间隔。AI 类型的体型比例、配额和追逐距离集中在 `core/progression.js` 的 `BOT_ROLES`。

游戏规则在 `core/` 中，不依赖 DOM 或 Canvas；`LocalSession` 对外提供 `start(viewSize, mode = "classic")`、`pause()`、`resume()`、`step(dt, input)` 和 `getSnapshot()`。输入格式是 `{ x, y, split, spore, target, view }`：前两项为方向向量，`split` / `spore` 表示本帧是否按下技能键，`target` 是鼠标目标的世界坐标 `{ x, y }`（键盘输入时为空），`view` 是世界坐标下的可见矩形 `{ left, top, right, bottom }`，用于公平出生。

快照的 `playerCells` 是玩家真实分身数组，`bots` 是 AI 的所有真实分身；每个球带有唯一的 `id`、控制者 `ownerId`、`mergeRemaining` 和弹射分量。`spores` 与 `spikes` 是独立可序列化实体；同一控制者共享技能冷却；渲染层按实体绘制，碰撞层按归属排除同伴。`player` 是按质量加权的球群摘要，提供总质量、平均速度、中心和 `viewRadius`，仅用于镜头与 HUD，不能拿它参与吞噬判断。快照还包含 `split`、`spore`、`stage`、`difficulty` 和 `peakMass`（最大球群总质量）；分裂、合体、吐孢子、扎刺、失去分身、阶段达标通过独立事件通知 UI。输入、模拟、绘制与 HTTP 存储相互分开，实体使用普通数据对象，便于后续定义网络消息。

音乐是独立的表现层模块 `audio/music.js`，不进入游戏世界和网络快照。`config.js` 中的 `music.tempo` 调整节拍、`music.defaultVolume` 调整首次播放音量，音符和和弦定义在音乐模块顶部。浏览器已保存的音量会优先于默认值；`orbit.music` 和 `orbit.music-volume` 分别保存音乐开关与音量。

`audio/effects.js` 同样只属于表现层，读取世界事件，不改变规则。它与音乐共享一个 AudioContext，以独立增益总线连接输出；`orbit.effects` 单独保存开关。联机接收服务端事件后直接复用音效模块，并筛选本人的技能、吞噬与复活事件。吐孢子和扎刺音色也定义在该文件顶部的 `CUES`，新增规则事件时可在此扩展。

`presentation/` 不修改实体或世界状态。`feedback.js` 从会话快照读取真实技能可用状态、富集区周期和游戏时间，分别供 UI 与绘制层使用；`config.js` 的 `feedback` 调整三类提示时长，`labels` 调整远处 AI 简化阈值。`labels.js` 接收屏幕坐标、文字测量尺寸、球体和 HUD 的几何范围，返回标签位置和引线起点，换用远程会话后也可继续复用。

快照包含 `leaderboard: { entries, player, total }` 和 `hotspots: { zones, remaining, duration, cycle }`。排行的 `player` 在前五名之外仍存在；每行包含 `ownerId`、`mass`、`cells` 和 `rank`。富集区及带有 `hotspotId` 的食物属于模拟状态，换位通过 `hotspots` 事件通知 UI。联机由权威服务器生成区域、采样食物、决定换位时间和排名，客户端只读取快照；生存局排名会保留已出局者。

单机生存模式通过 `start(viewSize, "survival")` 启动，快照包含 `mode`、`survival` 和 `result`。`survival` 包含 `remaining`、`duration`、`active`、`total`、玩家战绩、全名单排名及 `protectionByOwner`。`core/survival.js` 管理按控制者持久化的命数、击败数、死亡数和保护截止时间；`World` 在最后分身被吃时记录一次死亡，在本帧吞噬结束后才创建新球。`life`、`respawn`、`eliminated` 和 `gameover` 是独立规则事件，表现层读取事件后重定位镜头与显示提示。联机的这些规则位于 `server/game/world.py`，由服务器负责所有生命变更、复活位置与按 `RoomRules.duration` 封盘；单机生存仍为 300 秒。

`RemoteSession` 复用 Canvas、镜头、HUD、音频和标签布局，支持自动重连握手与 10 秒恢复凭证；`PositionBuffer` 仅平滑绘制坐标，不修改权威质量或碰撞。联机规则位于 `server/game/`，单机规则仍位于 `static/js/core/`；两端都用 `spatial.py` / `spatial-grid.js` 做候选筛选，修改共同玩法参数时应同步两端，并运行两套规则测试。

WebSocket 地址为 `/ws/arena`，使用浏览器原生 WebSocket。连接后服务器发送 `welcome` 分配玩家 ID 和 `resumeToken`；普通断开后客户端使用旧 token 发送 `resume`，服务端在 10 秒内把新连接绑定回原玩家。客户端用 `create` / `join`、`ready`、`configure`、`start`、`input`、`stop`、`leave`、`rematch`、`resume` 操作房间，`ping` / `pong` 测量延迟。`create` 与 `configure` 的规则为 `rules: { mode: "survival" | "teams", duration: 180 | 300 | 480 }`，配置权限与参数由服务器验证。`input` 仅包含 `roundId`、递增 `seq`、方向 `x/y`、鼠标目标 `target`、`split/spore`，身份由连接决定。每局分配新的 `roundId`，防止上局输入串入新局。

服务器发送 `room`（准备室与规则）、`state`（公开权威世界）、`foods`（食物全量）、`food_patch`（食物增量）、`record_saved`（记录已写库）、`error` 和 `left`。食物全量带 `version`；补丁带 `baseVersion`、`version`、`upsert` 与 `removed`，基线不符时客户端发送 `resync_foods` 请求全量，跨局和旧版本不会覆盖当前状态。世界事件使用递增 ID 和各连接发送游标去重，食物消费也通过 `foodId` 即时移除。每个连接仅保留最新位置和食物快照，慢客户端不会积压无界状态队列或阻塞其他人的模拟。`GET /api/network-info` 返回本机可用局域网网址，仅用于邀请提示。

单机仍由浏览器提交分数，HTTP 接口只验证格式；联机由服务器计算并存分。本版最高分是整个实例共用记录，没有账号身份。未来加入账号时，可扩展数据库为每位玩家和每场比赛保存记录。公网版本还应加入认证、跨进程共享房间和更长的会话恢复服务。
